# Third-party code and sources

What this project includes from others, what it follows without copying, and what it uses at run
time. The project's own license is in [LICENSE](../LICENSE).

## Dependencies

One Zig package, never in a build of the runner: [ianic/tls.zig](https://github.com/ianic/tls.zig) (MIT), the database's TLS until the network library's rustls replaced it, is a lazy dependency in `runner/build.zig.zon` that only `zig build test-tls-oracle -Dtls-oracle` fetches, to compare the old client with the new one (`runner/tls_oracle.zig`, docs/rust-net.md). Nothing of it is in the runner binary or the SBOM.

### Rust crates and libc (from the network library, `runner/rust/zr-net`, docs/rust-net.md)

Fetched by cargo at build time from crates.io, pinned by `runner/rust/zr-net/Cargo.lock` (cargo checks each crate's checksum; builds are `--locked`) and compiled into the runner as a static library. `cargo-deny` (`runner/rust/deny.toml`, `.github/scripts/cargo-deny.sh`) fails a build for a license outside MIT, Apache-2.0, ISC, BSD-3-Clause, Unicode-3.0 or Zlib, for an advisory, or for a source other than crates.io.

| Crate | Used for | License |
|---|---|---|
| [tokio](https://github.com/tokio-rs/tokio) | the runtime of the network library: the HTTP client's connections and requests | MIT |
| [rustls](https://github.com/rustls/rustls) | TLS to the database (`runner/src/pg.zig`, through `runner/src/tls_stream.zig`), with the `ring` crypto provider and rustls-webpki certificate checks | Apache-2.0 OR ISC OR MIT |
| [hyper](https://github.com/hyperium/hyper), [hyper-util](https://github.com/hyperium/hyper-util), [http](https://github.com/hyperium/http), [http-body-util](https://github.com/hyperium/http-body) | the HTTP/1.1 client (`runner/src/net_client.zig`): messages, framing and the connection state machine | MIT |
| [tokio-rustls](https://github.com/rustls/tokio-rustls) | TLS over the client's sockets | Apache-2.0 OR MIT |
| [socket2](https://github.com/rust-lang/socket2) | `TCP_USER_TIMEOUT`, keepalive and the call's socket pair | MIT OR Apache-2.0 |
| [rustls-native-certs](https://github.com/rustls/rustls-native-certs) | the system's root certificates, honouring `SSL_CERT_FILE` and `SSL_CERT_DIR` | Apache-2.0 OR ISC OR MIT |

The lock file lists the others (all permissive; the tokio skeleton adds `pin-project-lite`, MIT or Apache-2.0). The runner now also links Zig's bundled copies of [musl libc](https://musl.libc.org) (MIT) and LLVM's libunwind (Apache-2.0 WITH LLVM-exception), which Rust's standard library needs.

## Followed, not copied

- **GitHub Actions' runner protocol** (registration, the broker, the run and results services, the live log feed) is not publicly documented. The runner implements it in new Zig code, based on reading [`actions/runner`](https://github.com/actions/runner) and on running the same workflows on GitHub-hosted runners side by side. A few log messages reproduce `actions/runner`'s wording, so that logs read like GitHub's. `actions/runner` is under the MIT License, Copyright (c) 2019 GitHub, reproduced below.
- **Dagger's client protocol** is implemented in `runner/src/engine.zig`, based on [Dagger](https://github.com/dagger/dagger)'s documentation and source (Apache-2.0).
- Talking to GitHub's services is governed by GitHub's terms of service, which are separate from any of these licenses.

## Used at run time, not included

The Dagger engine pulls these images when jobs run; none of them is part of this repository or its builds:
- the Dagger engine image `registry.dagger.io/engine` (Apache-2.0);
- `ubuntu:24.04` and the Ubuntu packages provisioned into it (their own licenses), also published as
  `ghcr.io/open-blue/zig-runner-base` (the same image with the packages installed);
- `busybox` (musl build, GPL-2.0), pinned by digest in `runner/src/dagger.zig`, run unmodified inside job containers;
- `oven/bun` (MIT) and `node` (MIT), the JavaScript runtimes for actions;
- whatever images and actions workflows themselves name.

CI also fetches GitHub's expression test cases from [actions/languageservices](https://github.com/actions/languageservices) (`expressions/testdata`, MIT, Copyright GitHub) at a pinned commit, to check `runner/src/expr.zig` against them (`.github/scripts/expr-conformance.sh`); only case names are kept here, in `runner/tools/exprcorpus-failing.txt`.

The proofs in `proofs/` are checked with [Lean](https://lean-lang.org) 4 (Apache-2.0), which CI (`proofs.yml`) downloads from its GitHub release by pinned checksum (`.github/scripts/install-lean.sh`); they use no Lean library beyond Lean's own. They were ported from Agda proofs written for this runner in [zig-actions-runner](https://github.com/Lementknight/zig-actions-runner) (this project's own).

A development tool, `runner/tools/exprdiff` (Go, run by `.github/scripts/expr-diff.sh`), uses Gitea's [actionslib](https://gitea.com/gitea/actionslib) (MIT), pinned in its `go.mod`, to compare expression results on random expressions.

Another, `runner/tools/yamldiff` (Go, run by `.github/scripts/yaml-diff.sh`), uses [go.yaml.in/yaml/v3](https://github.com/yaml/go-yaml) (MIT and Apache-2.0), pinned in its `go.mod`, to compare `runner/src/yaml.zig` with it; the `action.yml` files it compares are fetched when it runs and not kept, and `runner/tools/yamldiff/repos.txt` lists only the repositories' names.

One more, `runner/tools/gitea-jobdiff` (Go, run by `.github/scripts/gitea-job-diff.sh`), uses the workflow model of the same actionslib (MIT, and [go.yaml.in/yaml/v4](https://github.com/yaml/go-yaml) under it, MIT and Apache-2.0), pinned in its `go.mod`, to compare the job `runner/src/gitea/job.zig` builds from a Gitea or Forgejo task with the one Gitea's model reads. The tasks it reads, `runner/src/gitea/testdata/corpus`, are what a local Gitea and Forgejo answered for this project's own test workflows, with their tokens and secrets replaced.

A third, `runner/tools/hashfilesdiff` (run by `.github/scripts/hashfiles-diff.sh`), runs [@actions/glob](https://github.com/actions/toolkit/tree/main/packages/glob) (MIT) 0.7.0, installed in a `node` container from `runner/tools/hashfilesdiff/package-lock.json` when it runs, under `reference.mjs`, which follows actions/runner's hashFiles script (MIT), to compare with `runner/src/glob.zig`. The lockfile pulls in minimatch 10.2.6, which is [BlueOak-1.0.0](https://blueoakcouncil.org/license/1.0.0) (minimatch moved from ISC to it within 10.x); nothing of it is copied into this repository, and Dependency review allows it by name (`security.yml`). `glob.zig` itself is a port of @actions/glob 0.7.0 and the part of [minimatch](https://github.com/isaacs/minimatch) it uses, written new in Zig from their source. That minimatch is the one @actions/glob 0.7.0 runs (`^10.2.5`, 10.2.6 when the port was written, 2026-10-26), [BlueOak-1.0.0](https://blueoakcouncil.org/license/1.0.0) like every minimatch from 10.1.0 (10.0.3 and before were ISC); the license asks that a copy of any part of it comes with its text or that link, which `glob.zig`'s header gives.

A fourth, `runner/tools/regexdiff` (run by `.github/scripts/regex-diff.sh`), runs a small C# program (`reference/`, this project's own) in Microsoft's [.NET SDK](https://github.com/dotnet/sdk) container (MIT) to compare `runner/src/regex.zig` with .NET's regular expressions; `matchers.txt` lists the problem matcher files on GitHub it reads patterns from, fetched when it runs and not kept.

Two more, `runner/tools/hpackdiff` and `runner/tools/rsadiff` (Go, run by `.github/scripts/hpack-diff.sh` and `rsa-diff.sh`), compare `runner/src/hpack.zig` with [golang.org/x/net/http2/hpack](https://pkg.go.dev/golang.org/x/net/http2/hpack) (BSD-3-Clause, Copyright The Go Authors), pinned in its `go.mod`, and `runner/src/github/rsa_sign.zig` with Go's standard library `crypto/rsa` (BSD-3-Clause).

CI runs these six weekly (`.github/workflows/compare.yml`); none of them is in any build.
